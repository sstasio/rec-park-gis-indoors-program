Tech Stack Reference

What each tool does and how it connects

📱

PIX4Dcatch

Mobile capture app (LiDAR + photogrammetry). Used for building exteriors, park hardscape, and site infrastructure. Syncs to PIX4Dcloud.

☁️

PIX4Dcloud

Cloud processing/storage for PIX4Dcatch projects. Bridges field capture to PIX4Dmatic processing without needing a desktop upload step in the field.

🖥️

PIX4Dmatic

Desktop processing engine. Turns PIX4Dcatch imagery into dense point clouds, textured meshes, and orthomosaics, georeferenced to WKID 7132.

🏠

Polycam

iPhone LiDAR scanning app. Used exclusively for building interior capture — produces point clouds and exportable DXF floor plans that feed ArcGIS Indoors.

🎥

Insta360 R2

360° camera for photo/video tours. Used across all spaces (interior + exterior) to build the walkthrough layer linked from facility pages.

📄

SharePoint

Document library for MOUs, plans, reports, and other file-based records. Not used for large media (photos/video/point clouds) — see the Storage page.

🗺️

ArcGIS Online (AGOL)

GIS system of record — Facilities, Units, Levels, Pathways, Scene Layers. Holds geometry and attributes, not raw media files.

🧩

Experience Builder / Hub

Public and internal web display layer. Popups link out to dedicated facility pages showing attributes, embedded 360° tours, photo galleries, and documents.

📡

Bad Elf RTK GNSS

Positioning backbone for every capture stream — ties PIX4Dcatch control points to WKID 7132 at centimeter accuracy via NTRIP correction.

Rule of thumb: AGOL stores where things are (geometry + attributes). SharePoint stores documents. The photo/video store (see Storage page) holds large media. Experience Builder/Hub stitches all three together for the end user.
